# 本地 Qdrant 评估数据库快照

此目录随仓库保留，配合[真实运行报告](../../results/README.md)展示持久化向量库。总大小约 31 MiB；内容为 Qdrant 本地模式的 SQLite 数据和集合配置，不是服务端的 snapshot 导出包。模型为 `qwen3-embedding:0.6b`，向量维度为 1024。

## 集合清单

| 集合 | 处理方式 | 状态 | 用途 |
|---|---|---|---|
| `kb_eval_1` | 1000 篇资料切分为 1528 个片段，每片最多 1024 字符 | 完整 | 当前已保存报告对应的集合 |
| `t2retrieval_eval_20261105_170203_33374` | 1000 篇资料，每篇一个向量 | 完整 | 重构前的历史集合，不对应当前报告 |
| `t2retrieval_eval_20261105_163354_28327` | 计划处理 10000 篇资料 | 未完成 | 保留的失败构建现场，不可用于评估 |
| `t2retrieval_eval_20261105_163633_29050` | 计划处理 10000 篇资料 | 未完成 | 保留的失败构建现场，不可用于评估 |

原始 `corpus`、`queries`、`qrels` Parquet 仍需另外下载。向量库保存了所选资料的正文片段、原始资料 ID、定位信息和向量，未把测试问题或标准标注写入候选资料。

## 使用注意

- 查看已保存的 Markdown/JSON 报告不需要模型、原始 Parquet 或打开此数据库。
- 重新执行评估需要匹配的原始 Parquet 和 Ollama；脚本检查模型、corpus SHA-256、完整性以及文档/片段数量。
- 只有 `build_complete is True` 的集合可用于评估，不能把计划数量当成失败集合的实际写入数量。
- 使用 `uv.lock` 固定的 Qdrant 客户端版本；同一数据库目录不能被多个进程同时打开。
- 数据库及其运行时锁文件是原样保留的展示文件。试用时建议复制到新的临时目录，通过 `--db-path` 使用副本，避免更新 Git 中保存的基线。
- 新实验使用新的集合名，不自动覆盖、删除或续传这些历史集合。重复保存大型二进制数据库会增加 Git 历史体积。

数据来源与结果限制见[报告说明](../../results/README.md)和[评估使用说明](../../README.md)。
